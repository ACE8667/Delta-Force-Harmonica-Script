# 音符指引项目开发交接文档

## 1. 项目概述

这是一个用于引导用户弹奏八音阶的项目。交互形式参考“钢琴块”，但目标不是游戏计分，而是让使用者根据下落音块判断按键时机。

当前八个音节及键盘映射：

| 音节 | C4 | D4 | E4 | F4 | G4 | A4 | B4 | C5 |
|---|---|---|---|---|---|---|---|---|
| 按键 | Z | X | C | V | B | N | M | , |

## 2. 当前文件

- `index.html`：页面结构、曲目信息、播放控制、BPM 输入和本地曲库操作
- `style.css`：黄绿色主题、透明度、八轨道背景、底部接音框、音块、本地曲库控件和响应式布局
- `demo.js`：默认《送别》曲谱（BPM 80）；`note` 选择音轨，`pitch` 是仅作提示的音名
- `app.js`：音符数据、统一时间轴、音块生成、命中判断、键盘输入和 Web Audio 音效
- 仓库根目录 `desktop/main.cjs`：Electron 桌面窗口入口，配置置顶、透明窗口、界面透明度及安全窗口控制 IPC；`desktop/preload.cjs` 提供受限的窗口控制桥接
- 仓库根目录 `package.json`：Electron 开发运行与 Windows 便携版打包脚本
- 浏览器版仍可直接打开；桌面测试版通过 `npm install`、`npm run start:desktop` 启动

## 3. 当前功能

- 八个音轨默认对应 C4 到 C5；曲谱编号 `note: 1–8` 映射到八个音轨，`note: 0` 表示休止
- 音块从上方持续下落
- 底部有一个横向连续的大接音框
- 键盘按键始终触发对应音效，不负责命中/移除音块；触屏直接点中接音框内音块时会移除该块
- 按住键盘或触屏琴键时显示无变色的下沉/内阴影反馈，直到松开；接音框高度为 64px 并贴齐演奏框底部
- 支持键盘输入
- 支持空格开始、暂停和继续
- Electron 桌面窗口支持透明背景；`desktop/main.cjs` 的 `OPACITY.all` 设置整体默认透明度，`frame`、`text`、`boxes`、`buttons` 可分别设置 `0–1` 覆盖整体值，设为 `null` 时继承整体值
- Electron 无边框透明窗口具有可拖动标题栏，以及最小化、最大化/还原和关闭按钮；透明演奏框保留八条可见音轨分隔线
- 首次开始后可通过播放控制旁的“重新播放”按钮从曲谱开头重播
- 曲谱通过 IndexedDB 保存在当前浏览器或桌面程序的本地用户配置中，无需后端；支持切换、保存、导入、导出和删除
- 使用 Web Audio API 生成简单正弦波音效
- 支持自定义 BPM（30–240 整数）；修改 BPM 会同步改变曲目推进速度和音块下落速度
- 支持设置曲谱循环次数（正整数，默认 2）；按曲谱所有 duration 的总拍数计算播放时长，到指定遍数后停止
- 开始演奏后，在整个演奏框按住鼠标左键降八度、右键升八度、中键升半音；松开对应按键后恢复原调
- 同时按住多个鼠标按键时，移调量按按钮组合即时计算；暂停、窗口失焦时清除按住状态
- 演奏框内鼠标操作仅用于临时移调，不触发音块命中；右键菜单与中键辅助点击默认行为被阻止
- 虚拟琴键标签随按住移调操作显示当前实际音名；松开后恢复原调标签
- 键盘快捷键始终按当前移调后的音高演奏；触屏可点虚拟琴键弹奏，鼠标只在演奏期间按住琴盘移调，不用于弹奏
- 休止符 `0` 只占用节拍时间和空间，不渲染虚线方框或数字

## 4. 节奏设计约定

默认曲谱位于 `demo.js`，由 `index.html` 在 `app.js` 之前加载。`note` 编号从 1 开始对应八个琴键，0 表示休止；非休止符的 `pitch` 用于显示移调提示，不改变按键实际发声；`duration` 为拍数。曲谱使用对象数组描述节奏：

```js
{ note: 1, pitch: "C3", duration: 1 } // Z 轨音块提示 C3，一拍
{ note: 2, pitch: "C#3", duration: 0.5 } // X 轨音块提示 C#3，半拍
{ note: 1, pitch: "C4", duration: 1.5 } // Z 轨音块提示 C4，一拍半
{ note: 1, pitch: "C5", duration: 2 } // Z 轨音块提示 C5，两拍
{ note: 0, duration: 1 } // 一拍休止
```

### 曲谱导入/导出 JSON 格式

导入和导出使用 UTF-8 JSON 单曲文件，格式标识及版本必须精确匹配。`title` 为 1–100 个字符，`bpm` 为 30–240 的整数，`chart` 至少包含一条事件；每个事件的 `note` 为 0–8，`duration` 为大于 0 的拍数。非休止事件（`note` 为 1–8）还必须提供符合音名格式的 `pitch`；休止事件（`note: 0`）不需要 `pitch`。

```json
{
  "format": "note-guide-chart",
  "version": 1,
  "title": "示例曲目",
  "bpm": 80,
  "chart": [
    { "note": 1, "pitch": "C4", "duration": 1 },
    { "note": 0, "duration": 0.5 },
    { "note": 2, "pitch": "C#4", "duration": 1.5 }
  ]
}
```

导入文件大小上限为 2 MB，单曲最多 10,000 条事件。曲谱导入后会写入本机 IndexedDB 并立即载入；导出当前曲谱为 `.note-guide.json` 文件，可用于备份或在其他设备导入。删除本地曲谱会要求确认；浏览器站点数据清除会移除本地曲库，因此重要曲谱应另行导出备份。

默认曲目为《送别》，BPM 为 80；用户可通过页面上的 BPM 数字输入框调整，允许范围为 30–240。曲目时钟以拍数累计：

```js
songClock += (deltaMs * bpm) / 60000;
```

所有音块按照统一的全局拍点时间轴生成，而不是按音轨分别累计位置。曲谱事件按顺序分配时间区间，不在同一时间区间生成多个音块。

每个音块的基础一拍高度同时作为该轨道的每拍下落距离：

```js
const beatDistance = width * (2 / 3);
const height = beatDistance * duration;
```

音块宽度填满轨道，四角为直角。不额外添加 `gap`；位置按事件结束拍定位，使后一个音块的底边与前一个音块的顶边处于同一水平线。音块每秒移动 `beatDistance * BPM / 60` 像素，修改 BPM 时，既有音块和后续曲谱继续使用同一拍数时间轴。初始提前 12 拍生成，确保音块仍从演奏框上方进入。

## 5. 音块视觉比例约定

用户提出的目标比例：

- 1 拍音块的高宽比应符合约定的 3:2 宽高关系
- 半拍高度为 1 拍的三分之一
- 音块高度等于基础一拍高度乘以时值，不额外添加间隔
- 曲谱事件连续时，后一个音块底边与前一个音块顶边相接，不重叠
- 同音轨或不同音轨的上下音块都不能重叠
- 音块宽度填满所在轨道，边缘与轨道边缘对齐

目前音块宽度直接取轨道宽度，并以轨道左边缘为定位基准。

## 6. 最近修复内容

此前出现过以下问题：

1. 不同音轨音块使用各自偏移，导致同一拍点错位
2. 同一音轨前后音块定位不一致，导致重叠
3. 新生成音块曾出现追赶节奏的快速下落
4. 音块宽度改变后没有同步背景轨道宽度，造成视觉偏移
5. 休止符被错误绘制为带数字的虚线框

最近的实现已改为统一拍数时间轴，并加入可自定义 BPM 控件和不可见休止符处理。后续开发时应优先保留这两个原则：

- 音块位置必须由全局节拍时间计算
- 音块速度必须统一由 BPM 和每拍垂直距离计算
- 暂停后继续演奏必须保留当前时间轴和已生成音块，不应重新开始曲目
- 音块按键弹奏只触发音效，不应自动从曲谱移除

## 7. 继续开发建议

建议下一步重点验证和完善：

1. 实际播放时观察连续音块是否首尾相接且没有重叠
2. 检查不同 duration 组合，例如 `1 + 0.5 + 0.5`、`1.5 + 0.5`、`2 + rest`
3. 根据实际窗口宽度微调轨道宽度对应的 `beatDistance`、接音框高度和音块尺寸
4. 将示例 `chart` 拆分为可编辑曲谱数据，后续支持导入简谱
5. 延音符 `-` 可以进一步建模为保持上一音轨音块连续延长，而不是只用 `duration` 表示
6. 可增加小节线、拍号、节拍指示和真实钢琴采样音

## 10. 重要开发约束

- 不要重新加入得分、连击、准确率，除非用户明确要求
- 保持八音节和当前按键映射，除非用户明确修改
- 反馈重点是“什么时候按键”，不是游戏成绩
- 音块宽度应一致并且中心对齐轨道线
- 连续音块之间不留额外空隙，后块底边与前块顶边对齐
- 休止符应为空白节拍，不显示方框

## 11. 源码模块索引

### `app.js`

代码按职责划分为以下模块。曲谱编号从 1 起、JavaScript 音符/轨道数组下标从 0 起；事件时序则由 `songClock`、`nextBeat` 和 `duration` 共同维护：

1. **配置与曲谱校验**：定义八个标准音、BPM 边界和入场提前量，并在启动时验证 demo 曲谱字段。
2. **DOM 与运行状态**：保存棋盘/按钮节点、播放时钟、循环目标、曲谱游标、活动音块、按住的按键和音频上下文。
3. **场景初始化**：按 `NOTES` 顺序建立轨道和虚拟琴键，再把键盘放入底部接音框。
4. **播放控制与动画**：开始时初始化负拍入场区间；暂停只停止帧循环，继续时从保存的时钟恢复；重新播放会取消旧帧并重置曲谱/音块状态；达到曲谱总拍数乘循环次数时结束。
5. **曲谱调度与音块布局**：按拍预生成曲谱事件且不超过循环目标；`note` 选择轨道，`pitch` 仅显示提示，`duration` 同时决定占拍区间和块高。
6. **接音框反馈**：通过 DOM 矩形相交更新音块就绪外观；触屏直接点中接音框内音块可移除该块，键盘弹奏不执行命中处理。
7. **鼠标移调与音频输出**：按下鼠标按钮集合重算临时半音偏移；`playNote` 将该偏移应用于基准琴键频率。
8. **输入与播放设置**：处理开始/暂停/完成后重播、键盘弹奏、持续按压反馈、鼠标移调、BPM 与循环次数校验。

### `style.css`

样式按主题变量、页面布局、曲目信息与控制、八音轨演奏框、接音框内键盘与音块、独立键盘、操作提示和窄屏布局分组。层叠顺序属于样式行为的一部分；整理时应保留选择器优先级和媒体查询覆盖关系。

### `index.html`

页面静态结构按曲目信息、BPM 控件与棋盘、操作提示组织。`#board` 是脚本创建音轨、接音框和虚拟键盘的挂载点；`demo.js` 必须先于 `app.js` 加载。

演奏框桌面基准尺寸为 `560 × 500px`；窄屏高度随视口缩放并设置最小高度。接音框使用 `bottom: 0` 锚定演奏框底部，内部虚拟琴键铺满接音框。棋盘宽度由 CSS 变量 `--board-width` 控制，容器和内部按键随之缩放。音块宽度填满各自轨道，音块坐标从接音框中线和统一拍数时间轴计算。
