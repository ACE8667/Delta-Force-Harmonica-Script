# 音符指引项目开发交接文档

## 1. 项目概述

这是一个无需安装依赖、可直接用浏览器打开的 Web 原型，用于引导用户弹奏八音阶。交互形式参考“钢琴块”，但目标不是游戏计分，而是让使用者根据下落音块判断按键时机。

当前八个音节及键盘映射：

| 音节 | Do | Re | Mi | Fa | Sol | La | Si | Do |
|---|---|---|---|---|---|---|---|---|
| 按键 | Z | X | C | V | B | N | M | , |

## 2. 当前文件

- `index.html`：页面结构、曲目信息、播放控制和倍率选择
- `style.css`：深色视觉界面、八轨道背景、底部接音框、音块和响应式布局
- `app.js`：音符数据、曲目节奏、统一时间轴、音块生成、命中判断、键盘输入和 Web Audio 音效
- 本项目没有 `package.json`，不需要 npm 安装依赖

## 3. 当前功能

- 八个音轨对应 Do 到高音 Do
- 音块从上方持续下落
- 底部有一个横向连续的大接音框
- 音块进入接音框后按对应键即可触发音效并消除音块
- 支持键盘、鼠标和触屏输入
- 支持空格开始、暂停和继续
- 使用 Web Audio API 生成简单正弦波音效
- 支持播放倍率：`x0.5`、`x0.75`、`x1.0`、`x1.5`、`x2.0`
- 休止符 `0` 只占用节拍时间和空间，不渲染虚线方框或数字
- 已移除得分、连击、准确率等游戏化统计

## 4. 节奏设计约定

当前 `app.js` 的 `chart` 使用对象数组描述节奏：

```js
{ note: 0, duration: 1 }       // 一拍
{ note: 1, duration: 0.5 }     // 半拍
{ note: 0, duration: 1.5 }     // 一拍半
{ note: 0, duration: 2 }       // 两拍
{ type: "rest", duration: 1 } // 一拍休止
```

当前实现采用 BPM 96：

```js
const BPM = 96;
const beatMs = 60000 / BPM;
```

所有音块按照统一的全局拍点时间轴生成，而不是按音轨分别累计位置。这样同一拍的不同音轨音块应处于同一水平线，避免跨音轨错位。

当前垂直节奏距离使用：

```js
const BEAT_DISTANCE = 124;
```

音块移动速度由 BPM 和播放倍率共同决定，播放倍率越高，曲目和音块移动越快。

## 5. 音块视觉比例约定

用户提出的目标比例：

- 1 拍音块的高宽比应符合约定的 3:2 宽高关系
- 半拍高度为 1 拍的三分之一
- 延音音块的高度应由一拍、半拍和中间间隔组成
- 前后音块之间必须保留明确的节奏间隔
- 同音轨或不同音轨的上下音块都不能重叠
- 音块宽度应统一适配背景轨道，并且中心对齐轨道中线

目前代码已把音块宽度改为根据当前轨道宽度自适应，并使用 `left: 50%` 配合 `translateX(-50%)` 居中。

## 6. 最近修复内容

此前出现过以下问题：

1. 不同音轨音块使用各自偏移，导致同一水平拍点错位
2. 同一音轨前后音块间隔不足，导致重叠
3. 新生成音块曾出现追赶节奏的快速下落
4. 音块宽度改变后没有同步背景轨道宽度，造成视觉偏移
5. 休止符被错误绘制为带数字的虚线框

最近的实现已改为统一时间轴，并加入播放倍率控件和不可见休止符处理。后续开发时应优先保留这两个原则：

- 音块位置必须由全局节拍时间计算
- 音块速度必须统一由 BPM 和倍率计算

## 7. 继续开发建议

建议下一步重点验证和完善：

1. 实际播放时观察同一拍的跨轨道音块是否严格处于同一水平线
2. 检查不同 duration 组合，例如 `1 + 0.5 + 0.5`、`1.5 + 0.5`、`2 + rest`
3. 根据实际窗口宽度微调 `BEAT_DISTANCE`、接音框高度和音块尺寸
4. 将示例 `chart` 拆分为可编辑曲谱数据，后续支持导入简谱
5. 延音符 `-` 可以进一步建模为保持上一音轨音块连续延长，而不是只用 `duration` 表示
6. 可增加小节线、拍号、节拍指示和真实钢琴采样音

## 8. 运行方式

直接在浏览器打开 `index.html` 即可：

```text
index.html
```

也可以在 VS Code 中使用 Live Server 等静态文件服务器打开。当前不需要构建步骤。

## 10. 重要开发约束

- 不要重新加入得分、连击、准确率，除非用户明确要求
- 保持八音节和当前按键映射，除非用户明确修改
- 反馈重点是“什么时候按键”，不是游戏成绩
- 音块宽度应一致并且中心对齐轨道线
- 音块之间应有可见且符合节奏的上下间隔
- 休止符应为空白节拍，不显示方框
